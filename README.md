Find QA/SDET (or any role) openings at product companies → verify they match → apply
with **your** tailored resume → email recruiters → track everything. Cross-platform
(macOS / Linux / Windows). Zero hardcoded secrets — every personal value lives in a
git-ignored `config/user.json` that you create with one interactive wizard.

---

## ⚡ Quick start (5–10 min, one time)

```bash
git clone <this-repo> apply-autopilot
cd apply-autopilot

python3 hub.py onboard    # 1. GUIDED: reads your resume → confirm/correct every field → profile
python3 hub.py install    # 2. INTERACTIVE: shows missing deps + commands (brew/apt/winget) → installs all
python3 hub.py start      # 3. starts the browser stack (:9000 ctl + :3000 MCP)
python3 hub.py health     # 4. verify everything is green (6 tests)
python3 hub.py eval       # 5. readiness evaluation — test cases + % success rate
python3 hub.py test       # 6. full test suite (skills/code/logic/mcp/searxng/parsing)
```

Windows users run the same commands (`python` instead of `python3`), or double-click
`setup.bat` → `install.bat` → `run.bat`.

> **First run:** just `python3 hub.py` (no arguments). The repo ships with **zero
> personal data** — no name, email, phone, resume, employer, salary, or credentials —
> so it detects the missing `config/user.json` and offers to launch guided onboarding.
> Your data is written once to `config/user.json` (git-ignored, `chmod 600`) and you are
> never asked twice.

`onboarding.py` walks you through it step by step: it asks setup questions, **grills you
with interview-style questions** to extract your skills/achievements, clearly explains how
Gmail is used (OTP reads, ATS sign-ups, recruiter cold emails) and asks for consent, then
generates a tailored profile (`config/profile.md`) so you are **never asked twice**.

**No secrets live in this repository.** For coding agents, start at `AGENTS.md`.

## What it does

| Stage | Tool | Command |
|---|---|---|
| Find | product-company QA openings (ATS APIs) | `python3 hub.py start` then `python3 -m find.prod_sweep` |
| Find | LinkedIn Easy Apply batch | `.venv/bin/python find/sweep.py 10` |
| Apply | InstaHyre 1-click | `.venv/bin/python apply/ih_sweep.py <urls>` |
| Apply | LinkedIn auto-apply | `.venv/bin/python apply/li_drive.py <jobid>` |
| Track | applied vs not-applied report | `python3 hub.py track` (or `track.sh`) |

On Windows use `.venv\Scripts\python.exe` instead of `.venv/bin/python`, or the `.bat` files.

## Resume — EXACT file + MD5 gates (mandatory)

- Canonical resume path comes from `config/user.json → resume_path` (never a bare `resume.pdf`).
- The upload filename is **`Firstname_Lastname_Role.pdf`** (auto-derived in `setup.py`) — recruiters reject generic `resume.pdf`.
- Known-good MD5 is stored in `config/resume.md5` (generated by `setup.py`).
- Every apply script calls `core/resume_secure`: **`PICK()` → `BEFORE_UPLOAD()` → `POST()`**,
  so the exact verified bytes are always uploaded and re-checked after submit.

```bash
.venv/bin/python core/resume_secure.py    # verify + run the three gates
```

See `skills/resume/SKILL.md`.

## Architecture (SOC)

```
core/    ctl.py (CDP :9000) · browser.py (:3000 MCP) · capsolver.py · see.py (OCR)

apply/   li_drive · ih_sweep · fill_gh_fast · li_listed_apply
find/    prod_sweep (ATS APIs) · product_companies_builder/lookup · tracker_reconcile · sweep
config/  answers.py (single source of truth) · user.json.example · data/product_seed.py
skills/  apply · find · verify · email · resume · track · learn · ops (+ ATS recipes)
hub.py   cross-platform CLI (setup/install/start/stop/health/track/doctor)
setup.py · runtime/server.py · README.md · product_companies.md
```

## DRY: one place for your data

`config/user.json` → loaded by `config/answers.py` (`A` dict) → used by every script.
Change your phone/CTC/resume once, everything updates.

## Speed & reliability rules baked in

- Concurrent ATS checks · short timeouts · one-eval-per-action · no probing loops
- File-based scripts · same-eval fill+submit (React re-render fix) · real typing for React inputs
- Hard proof gate after every submit (no confirmation text = not counted as applied)

## Track

`config/progress.json` — total apps, per-company, per-channel, blocked reasons.
Run `python3 hub.py track` for the applied vs not-applied report.
